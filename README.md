# AI Product Assistant — Генератор B2B-карточек товаров

1. Клонировать репозиторий и перейти в него:

   ```bash
   git clone https://github.com/EndoKardo/AI-product-assistant-for-description-test-task.git
   cd AI-product-assistant-for-description-test-task
   ```

2. Создать и активировать виртуальное окружение:

    ```bash
    python -m venv .venv
    #Для Windows: 
    .venv\Scripts\activate
    #Для Linux/macOS: 
    source .venv/bin/activate
   ```
   
3. Установить зависимости:

    ```bash
    pip install -r requirements.txt
   ```
   
4. Создать файл .env в корне проекта и добавить туда API-ключ OpenRouter.ai:

    ```text
    OPENROUTER_API_KEY=ваш_ключ_сюда
   ```
   
5. Запустить сервер:

    ```bash
    uvicorn app.main:app --reload
    ```
   
6. Открыть в браузере: http://127.0.0.1:8000

# 🖥 Как пользоваться

На главной странице доступно два способа ввода:

1. Способ 1: Форма ввода. 
Заполняете поля: название товара, производитель, описание, а также вводите 
характеристики в формате Ключ: Значение (каждая с новой строки). Код сам собирает из этого JSON.

2. Способ 2: JSON.
Вставьте готовый JSON-объект.

После нажатия «Сгенерировать» сервис отправляет данные в LLM и после получения ответа от LLM, сервер отправляет готовый Markdown-текст и показывает его на новой странице.

# 🧠 Краткое описание использованных промптов и принятых решений

Для генерации карточки используется System Prompt в связке с JSON-данными, которые передаются в User Prompt. При написании промпта были применены следующие техники:
1. Role Prompting: в самом  начале модели задается роль профессионального B2B-копирайтера и SEO-специалиста. Это настраивает тон генерации на строгий, технический и деловой.
2. Задание формата вывода: в промпт прописан жесткий шаблон того, как должен выглядеть блок характеристик. Это заставляет модель строго следовать формату списка и не использовать лишние символы.
3. Защита от галлюцинаций: в промпт используется строгое правило: "Используй ТОЛЬКО те данные, которые переданы в JSON" и "КАТЕГОРИЧЕСКИ ЗАПРЕЩЕНО выдумывать технические характеристики". Это важно для B2B, чтобы неройсеть не приписала прибору несуществующие свойства.
4. Обработка неполных данных: "Если параметра нет в JSON — ОБЯЗАТЕЛЬНО напиши: "данных нет"". Это решает проблему, когда контент-менеджер забывает заполнить поле, а нейросеть молча его пропускает. Теперь менеджер видит плашку и понимает, что нужно уточнить у инженера.
5. Структурирование вывода: в конце промпта задан четкий каркас ответа в формате Markdown (SEO-заголовок, описание, характеристики, запросы, коммерческий блок). Это позволяет легко отображать результат и дает контент-менеджеру готовый к копированию текст.

# ⚠️ Список ограничений решения и возможных улучшений

Текущая реализация имеет следующие ограничения:
1. Стабильность бесплатной LLM: в проекте используется бесплатная модель через OpenRouter. Бесплатные модели могут иногда игнорировать часть инструкций или работать медленнее.
- Улучшение: перейти на платные API, которые будут отличаться более качественной генерацией, стабильностью и скоростью.
2. Отсутствие базы данных: результаты генерации не сохраняются. При закрытии страницы, текст пропадает.
- Улучшение: подключить БД для кэширования результата (чтобы не платить за повторную генерацию) и сохранения истории.
3. Строгая валидация только по структуре: сейчас pydantic проверяет, что поля name и description являются строками, а specs - словарем.
- Улучшение: разработать валидаторы, которые будут требовать/проверять наличия нескольких технических характеристик для запуска генерации.
4. Парсинг формы: в левой форме характеристики вводятся вручную в формате `Ключ: Значение`. Если пользователь ошибётся с двоеточием, поле проигнорируется.
- Улучшение: сделать динамичную форму на фронтенде, где менеджер сможет добавлять пары "ключ-значение" кнопкой "+ Добавить характеристику".
